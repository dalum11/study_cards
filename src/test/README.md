# StudyCards test — тесты для создания колод карточек
Тесты для SpringBoot-приложения с JWT-аутентификацией.
**Технологии:**
- JUnit5
- AssertJ
- Mockito
- RestAssured
- Testcontainers
- H2
- Jacoco

## Структура тестов
```

src/test/java/com/th3curiosity/studycards/
├── base/                    # Базовые классы для тестов
│   ├── BaseApiTest.java     # Общая настройка для API-тестов
│   └── BaseApiAssertions.java # Общие проверки для API-тестов 
├── config/                  # Конфигурации тестовой среды
│   └── TestContainersConfig.java # PostgreSQL через Testcontainers
├── data/                    # Константы для тестов
├── utils/                   # Утилиты для генерации тестовых данных
└── tests/
    ├── unit/                # Юнит-тесты (быстрые, моки)
    │  ├── service/          #   - тесты сервисов
    │  └── exceptions/       #   - тесты GlobalExceptionHandler
    └── integration/         # Интеграционные тесты (медленные, реальные зависимости)
       ├── controller/       #   - API-тесты (Testcontainers + PostgreSQL)
       └── repository/       #   - репозитории (H2, JPA-маппинг)

```

## Типы тестов и их назначение
### Юнит-тесты - находятся в директории src/test/java/com/th3curiosity/studycards/tests/unit
**Цель:** Проверить бизнес-логику изолированно

**Скорость:** Очень быстрые, не требуют поднятия контекста приложения

**Инструменты:** Mockito, AssertJ

**Расположение:**
- `service/` - изолированные тесты сервиса с моками 
- `exceptions/` - изолированные тесты обработчика исключений

**Что проверяют:**
- Условия, ветвления, расчёты
- Проверка, бросает ли сервис нужное исключение
- Проверка вызова методов (verify)

**Что НЕ проверяют:**
- Реальную работу с БД (это задача интеграционных тестов)
- JPA-маппинг

### Интеграционные тесты - находятся в директории src/test/java/com/th3curiosity/studycards/tests/integration
**Цель:** Проверить JPA-маппинг и контракты методов

**Скорость:** Медленные, поднимают весь контекст приложения

**Инструменты:** RestAssured, H2, PostgreSQL, Testcontainers

**Расположение:**
- `controller/` - тесты контроллеров, без моков
- `repository/` - тесты репозиториев, без моков

**Что проверяют:**
- Методы репозитория
- Негативные запросы
- Контрактные тесты
- Граничные значения

**Что НЕ проверяют:**
- Нет проверок для всех методов репозиториев

**Почему тесты репозиториев и контроллеров используют разные БД:**

H2 для тестов JPA-репозитория:
1) Высокая скорость
2) Изоляция автотестов
3) Не требуется запускать Docker
4) Достаточна для проверки маппинга


PostgreSQL-контейнер для тестов контроллеров:
1) Воспроизводится реальное окружение
2) H2 поддерживает не все специфичные Postgres-функции
  

### Вспомогательные классы для тестирования - нужны для настройки тестовой среды, инкапсуляции логики и создания тестовых данных
Находятся в директории src/test/java/com/th3curiosity/studycards
- `base/` - базовые классы - нужны для инкапсуляции логики и вынесения общих методов
- `config/` - классы для настройки тестовой среды
- `data/` - классы с константами для использования в тестах
- `utils/` - утилитные класссы, упрощают работу с тестовыми данными и написание автотестов

## Работа с тестами

### Интеграционные тесты - тесты контроллера
Проверяют полный путь от отправки запроса до взаимодействия с БД PostgreSQL
#### Инициализация тестовых данных
Для инициализации тестовых данных используется файл init.sql с минимально заполненными данными для тестирования.
Файл нахожится в директории src/main/resources/db/init.sql
#### Настройка тестовой среды
За тестовые контейнеры отвечает файл TestContainersConfig - он находится в директории /config и создаёт контейнер для 
PostgreSQL с профилем test. Запускает инициализацию данных в БД с помощью init.sql

Тесты запускаются на случайном порту с помощью классса BaseApiTest - он тоже использует профиль test и содержит 
конфигурацию для всех тестов контроллера. В этом классе есть общие для интеграционных тестов методы - авторизация 
пользователя

### Интеграционные тесты - тесты репозитория
Проверяют JPA-маппинг и контракты методов
#### Инициализация тестовых данных
Все данные инициализируются в тестах репозитория в отдельной H2-БД. Файл init.sql не используется
#### Настройка тестовой среды
H2-БД настраивается автоматически, дополнительно ничего не нужно

### Юнит-тесты - тесты сервиса
Изолированные тесты. Проверяют бизнес-логику на моках
#### Инициализация тестовых данных
Для создания тестовых данных используются утилитные классы из директории utils
#### Настройка тестовой среды
Всё настроено в самих тестах, никаких дополнительных действий не нужно

### Юнит-тесты - тесты обработчика исключений
Проверяют работу обработчика на моках
#### Инициализация тестовых данных
Данные создаются в самом тесте, дополнительные данные не нужны
#### Настройка тестовой среды
Для настройки используется базовый класс BaseExceptionTest - он использует профиль test и импортрует конфиги из 
TestContainersConfig

### Быстрый запуск

### Все тесты
```bash
./mvnw test
```

Только юнит-тесты

```bash
./mvnw test -Dtest="*Test" -DfailIfNoTests=false
```

Только интеграционные тесты репозиториев (быстрые)

```bash
./mvnw test -Dtest="*RepositoryTest"
```

Только интеграционные тесты контроллеров (с Docker)

```bash
# Docker Desktop должен быть запущен
./mvnw test -Dtest="*ControllerTest"
```

С отчётом о покрытии

```bash
./mvnw clean test jacoco:report
# Отчёт: target/site/jacoco/index.html
```
